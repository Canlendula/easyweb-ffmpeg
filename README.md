# easyweb-ffmpeg · Frame 本地视频工作台

用浏览器操作本机 FFmpeg。无 npm 依赖、无构建步骤；Node.js 运行本地服务，原生 HTML / CSS / JavaScript 提供界面。

素材由本机 CPU / GPU 处理，不上传云端。当前主要在 Windows 上验证，界面名称为 **Frame**。

## 启动

需要 Node.js 20+，以及带 `ffmpeg` / `ffprobe` 的本地 FFmpeg 安装。

克隆仓库后直接启动，无需执行 `npm install`：

```powershell
git clone git@github.com:Canlendula/easyweb-ffmpeg.git
cd easyweb-ffmpeg
npm start
```

Windows 双击 **`start.cmd`**，会启动服务并打开浏览器。也可在本目录执行：

```powershell
npm start
```

访问 **http://127.0.0.1:3210**。关闭启动窗口或按 `Ctrl+C` 停止服务。另一个端口：`$env:PORT=3211; npm start`。

程序从 PATH、Windows WinGet 安装目录自动检测 FFmpeg。可在网页右上角设置中填写两个可执行文件的完整路径，也支持 `FFMPEG_PATH`、`FFPROBE_PATH` 环境变量。

### 裁剪的三种导出目标

- **保持原编码（默认）**：直接复制音视频，原画质保留，沿用 MP4 / MOV / MKV / WebM 容器（其他输入使用 MKV）。无需设置处理设备和码率。按附近关键帧裁剪，实际起止时间可能略有偏差。
- **体积优先**：按所选时间精确裁剪，默认 H.264 / MP4，视频目标码率参考原片视频码率的 65%，音频为 AAC 128 kbps。元数据缺失时按文件信息或画面尺寸估算推荐值。界面显示目标码率对应的预计体积；实际体积可能浮动。
- **画质优先**：按所选时间精确裁剪，默认 H.264 / MP4，按画面内容分配码率、AAC 192 kbps。不限定输出体积。

后两项默认保留分辨率和帧率。展开 **高级设置** 可选择 H.264 / H.265 / AV1、切换目标码率或按画质分配码率、设置视频 Mbps 和音频 kbps，并切换 MP4 / MKV。可恢复推荐值；同一个素材内切换导出目标会保留各自已修改的设置。重新编码无法增加原片已有的细节。

所有需要编码的工具均默认 **自动选择设备**：完成本机检测后，优先使用可用显卡，无可用显卡时选 CPU。下拉框会显示实际自动选择的设备，也允许手动选择 CPU 或显卡。保持原编码只做流复制，不调用硬件编码器。

### 读取本地文件

- **推荐：添加素材 / 粘贴路径。** 服务直接读取原文件，视频不需要复制。文件浏览器支持目录跳转、多个文件、中文路径。
- **拖拽 / 系统文件选择器：** 浏览器无法提供原文件绝对路径，因此流式复制到本机 `.data/imports/`，不上传云端。这些临时副本不提供“替换原素材”按钮。大型文件建议使用直接路径。
- 浏览器不支持某些编码时，仍可导出。点击“生成兼容预览”创建完整低清 H.264 副本；最终输出依然使用原素材。

### 音量调整

**音量调整** 是独立工具；原“音频工具”更名为 **音轨工具**，继续提供提取、移除和替换音轨。

- 直接输入非负、可计算的倍率，支持自定义小数及科学计数法。`0.5` 为减半（约 -6.02 dB），`2` 为两倍（约 +6.02 dB），`0` 为保留音轨但完全静音。倍率代表信号幅度，听感不一定按相同比例变化。
- 提供 0.25 / 0.5 / 1 / 1.5 / 2 / 4 倍快捷按钮和 0～4 倍滑块。输入框可以填写超出滑块范围的值，不会自动压回 4 倍。
- 放大时默认启用 **峰值保护**，使用 FFmpeg `alimiter` 将处理中的采样峰值限制在 0.95，关闭自动增益补偿并补偿滤镜延迟。可减少削波，但会压低过高的峰值，实际增益可能小于设定值；不保证消除原文件已有失真或有损编码引起的峰值变化。1 倍及衰减时不运行该限制器。
- 0 倍、低于 0.1 倍、高于 4 倍，或关闭峰值保护后放大，都会显示原因并要求勾选“仍按当前设置处理”。修改设置或更换素材会清除确认。后端也检查确认，用户明确选择后允许处理，不私自修改倍率。
- 音频文件自动沿用 MP3 / M4A / WAV / FLAC 格式，其他输入默认输出 M4A；也可手动选择。MP3 / AAC 为 192 kbps，WAV / FLAC 为 24-bit。调整音量需要重新编码音频；有损来源转成 WAV / FLAC 无法补回已经丢失的细节。
- 视频可保留画面或仅导出所选音轨。保留画面时，视频及其他音轨直接复制，仅将所选音轨调音量并重新编码为 AAC；MP4 / M4V 输入自动输出 MP4，其他视频默认 MKV，也可手动选 MP4 / MKV。字幕、封面、附件及原数据轨道不导出，所选容器必须支持保留的编码。
- 左侧播放原素材，处理结果需从任务队列预览。每次处理生成新文件，不直接改变原文件；视频结果仍可使用既有的“替换原素材”流程。

滤镜依据：[FFmpeg volume](https://ffmpeg.org/ffmpeg-filters.html#volume)、[FFmpeg alimiter](https://ffmpeg.org/ffmpeg-filters.html#alimiter)。

### 替换视频封面

在 **替换封面** 中添加原视频，再选择一张 JPG / PNG 静态图片（最多 32 MB、6400 万像素）。支持直接浏览本地图片或通过系统文件选择器导入，新旧封面可并排查看。点击“开始处理”生成新视频；完成后也支持改名、备份或直接覆盖原素材的两次确认流程。

- 支持 MP4、M4V、MKV，输出沿用原容器。所有音视频轨道直接复制，不调整码率、不插入视频帧；字幕、章节和其他附件也会保留。封面保留原尺寸和比例，不裁切。
- MP4 / M4V 使用 `attached_pic`；MKV 使用标准命名的 `cover.jpg` / `cover.png` 附件，替换旧的标准封面，不累积多张封面。其他图片附件通过临时提取、重新附加保留原内容，临时文件在任务结束后删除。
- 这是**内嵌封面**。播放器和文件管理器可能选择自行截取画面，也可能缓存旧缩略图，无法保证 Windows 资源管理器马上显示新图片。不会为了缩略图更换视频第一帧。
- FFmpeg 会重新写入容器，所以整个文件的字节、部分容器元数据会变化，MKV 时长头可能有毫秒级重算差异。测试逐包核对音视频内容、时间戳与时长，确认媒体内容保持不变；不支持的封装会提示，避免自动转码。

依据：[FFmpeg 的内嵌封面和附件说明](https://ffmpeg.org/ffmpeg.html#Main-options)、[Matroska 封面附件规范](https://www.matroska.org/technical/attachments.html)。

### 替换原素材（两次确认）

单个直接读取的原视频完成导出后，任务卡片提供 **替换原素材**：

1. 第一次确认：编辑替换后的文件名，选择“保留原片备份”或“直接覆盖”，核对完整保存路径。可省略扩展名，程序会按导出格式补齐；不会覆盖其他无关的同名文件。
2. 第二次确认：再次核对原文件和新文件路径后执行，不必抄写原文件名。直接覆盖还需要勾选“了解无法还原”。确认令牌两分钟过期、只能使用一次，并绑定第一次确认的名称和方式。

执行时会再次核对原文件和导出文件有没有变化。默认的 **保留原片备份** 将原视频移至其所在目录的 **`.frame-backups/`**，将导出结果放回原素材目录，允许使用新文件名；导出目录不再额外保留副本。每次操作只保留当前视频与一份原片备份。排队处理中的素材不能替换。

**直接覆盖** 不保留本次原片备份：先完整放置处理结果，成功后移除原片和多余导出副本。改名时原文件也会被移除，只保留新名称的处理结果。覆盖后**无法通过本工具还原**；其他任务已有的历史备份不会被自动删除。操作中途失败会尝试回滚，若文件锁或权限问题阻止回滚，将报告原片保留的位置。

保留备份模式的任务卡片提供 **恢复原素材**，同样需要两次确认。恢复时将原片移回原位置并恢复原名，将处理后版本移到备份目录，不额外复制；仍只保留这两个版本。直接覆盖不提供恢复按钮。任务中的预览、另存副本与打开位置会跟随处理后文件的实际位置。如果文件后来被修改，停止自动恢复，可手动从备份目录找回原文件。拼接、图片、GIF、纯音频输出和拖入的临时副本不提供视频替换功能。

### 清理空间

打开 **任务队列 → 清理空间**，查看可释放空间并选择文件，核对清单后确认清理。

- 默认选中旧版替换 / 恢复遗留的重复文件和未使用的导入副本、预览与中间文件。删除重复文件前会比较完整内容；内容不同或文件变化时跳过。
- 原片备份和恢复后保留的处理版本默认不选中。主动勾选并清理后，对应的恢复或处理结果入口将不可用；任务记录继续保留。
- **导出文件（默认不勾选）**：可按组全选或逐个勾选，展示名称、完整路径及占用空间。包括任务记录中的普通导出结果（含自定义目录），以及项目 `outputs/` 中已不在最近 100 个任务内的媒体文件；即使从未使用替换功能，也能清理。清理后预览、另存副本、打开位置和替换入口失效，任务记录继续保留。
- 源素材、替换后的当前视频，以及本次服务会话中加载的素材、图片和预览不列入导出清理。已被其他任务作为输入使用的导出也会保留。处理、加载和替换过程中禁止执行清理，执行前再次检查文件是否变化。
- 仅在项目专用 `outputs/` 扫描当前层的常见导出媒体文件，不进入子文件夹，不跟随符号链接，也不清空任意自定义输出目录。自定义目录只列出任务记录中的具体文件。历史独立任务的备份可单独勾选。清理重复导出后，任务入口会改为保留文件的位置。
- 清理是永久删除，需要在页面内确认。共享同一底层数据的硬链接不重复计入预计释放空间；磁盘实际变化还受文件系统影响。

### 打开位置与另存副本

日常查看已有结果，使用 **打开位置** 即可。原“下载”已改名为 **另存副本**：它通过浏览器再保存一份现有文件，不重新处理视频，会额外占用磁盘空间。适合需要浏览器保存到其他位置，或文件夹打开失败时使用；浏览器是否询问保存位置取决于其下载设置。服务只监听本机，不提供远程下载。

Windows 的 **打开位置** 会先查找并复用对应目录的资源管理器窗口，缺少窗口时使用 [SHOpenFolderAndSelectItems](https://learn.microsoft.com/en-us/windows/win32/api/shlobj_core/nf-shlobj_core-shopenfolderandselectitems) 创建。随后显式显示窗口、恢复最小化状态、选中文件并尝试切到前台，支持中文和空格路径。接口会验证目录匹配、窗口可见及非最小化状态；进程退出成功或窗口句柄存在不算打开成功。如果 Windows 限制前台激活，页面会区分“窗口已显示但未切到前台”，避免误报成功。参见 [Windows 前台窗口规则](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setforegroundwindow)。

### 本机协议助手（实验功能，默认停用）

默认的“打开位置”使用服务端调用 Windows 文件管理器的方式，无需安装助手。Windows 可能限制前台激活，页面会如实提示窗口状态。

`native/` 和 `scripts/native-bridge.mjs` 保留了通过自定义 URL 协议唤起助手的实验代码。浏览器调用链尚未验证可用，不属于正常使用步骤，也不保证解决前台激活问题。

## 处理边界

- “保持原编码”按关键帧定位，可能保留所选边界之外的帧；需要准确时使用体积优先或画质优先。参见 [FFmpeg 关于 seek 与 streamcopy 的说明](https://ffmpeg.org/ffmpeg.html)。码率控制参考 [FFmpeg 编码参数文档](https://ffmpeg.org/ffmpeg-codecs.html)。
- CPU / NVIDIA / Intel / AMD / Apple 编码选项取决于当前 FFmpeg 构建、硬件和驱动。GPU 编码器会实际运行两帧测试，失败的不会提供为导出选项。解码、滤镜仍可能使用 CPU。
- 质量选项控制编码器的质量参数，不保证输出文件一定更小，重新编码通常有损。
- 常规重编码输出为 8-bit `yuv420p`；未实现 HDR 色调映射。检测到 HDR 时提示颜色风险。需保留 HDR 可使用适用的流复制操作。
- 常规视频重编码 / 裁剪 / 拼接保留第一条视频与第一条音轨，字幕、附件和数据轨道不导出。提取音频可选择音轨；封装转换保留所有音轨。
- 快速拼接做参数预检，但无法保证所有编码参数完全一致；异常时切换兼容拼接。参见 [FFmpeg concat demuxer](https://ffmpeg.org/ffmpeg-formats.html#concat-1) 与 [concat filter](https://ffmpeg.org/ffmpeg-filters.html#concat)。
- GIF 最长 60 秒。兼容预览生成最长运行 30 分钟；长视频推荐先导出可播放格式。服务重启后未完成任务标记中断，不自动重跑；需重新添加素材。任务历史保留最近 100 条。
- 替换安装使用同目录硬链接以拒绝覆盖冲突文件，适合 Windows NTFS 等支持硬链接的文件系统。FAT / exFAT 等不支持的文件系统会安全报错；可手动管理导出文件。备份不自动清理。

```text
outputs/               默认导出目录
```

服务仅监听 `127.0.0.1`，校验 Host / Origin；修改请求必须携带当前会话随机令牌。所有 FFmpeg 操作使用参数数组启动进程，不运行用户提供的 shell 命令。媒体网络协议关闭；输出不覆盖已有文件。此工具用于个人电脑，不提供局域网 / 多用户部署模式。

停止服务后，可按需清理 `.data/imports/` 中的导入副本和 `.data/work/` 中的预览 / 中间文件。`.data/jobs.json` 保存导出与恢复记录；如删除此文件，需要自行保管 `.frame-backups/` 中的原文件备份。

`.gitignore` 排除本地设置与历史、导出文件、测试素材及结果、原片备份、处理临时文件和 `.env` 配置。自定义输出目录如果位于仓库内，也应将对应目录加入 `.gitignore`，避免提交个人媒体文件。

## 验证

```powershell
npm test
npm run test:integration
npm run test:cover
npm run test:volume
```

集成测试会在 `test/fixtures/` 生成测试素材、在 `test/results/` 输出结果，以独立端口运行测试服务，覆盖真实转码、裁剪、拼接、音频、GIF、截图、队列取消、范围请求和替换确认。仅操作自行生成的测试文件。

`test:cover` 使用独立的测试目录与 3221 端口，覆盖 MP4 / M4V / MKV 的新增与替换封面；逐包核对两条视频、两条音频、字幕、章节、标签及无关附件，并校验可选导出清理、原片保护与已清理任务的失效入口。

`test:volume` 使用独立的测试目录与 3223 端口，测量实际音量增益、峰值和采样数量，验证极端倍率确认、音频格式、音轨选择，以及视频和未调整音轨的逐包内容与时间戳。
